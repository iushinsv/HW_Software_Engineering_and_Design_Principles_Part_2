# HW1. Микросервисная архитектура: Currency Rate Provider & Rate Printer

## Общее описание

В рамках домашнего задания №1 реализована система из двух взаимодействующих микросервисов на платформе **Java 17 + Spring Boot 3.5**. Система демонстрирует принципы синхронного межсервисного взаимодействия через REST API, модульность и разделение ответственности (Separation of Concerns).

Архитектура построена по клиент-серверной модели: один сервис предоставляет данные (провайдер), второй — потребляет их (клиент).

---

## Сервис 1: Currency Rate Provider

**Назначение:** Предоставление текущего курса валютной пары USDRUB через синхронный RPC-интерфейс.

### API

- **Endpoint:** `GET /api/rates/usdrub`
- **Протокол:** HTTP, синхронный
- **Формат ответа:** JSON
- **Пример ответа:**
  ```json
  {
    "currency": "USDRUB",
    "rate": 80.15
  }
  ```

### Логика формирования курса

Базовое значение курса — 80.0 рублей за доллар. Для имитации рыночных колебаний на каждый запрос генерируется случайное отклонение в диапазоне ±2.0 рубля. Результат округляется до двух знаков после запятой. Таким образом, значение курса не является константой и изменяется при каждом обращении.

### Техническая реализация

- **Язык:** Java 17
- **Фреймворк:** Spring Boot 3.5
- **Зависимости:** Spring Web (включает встроенный Tomcat)
- **Порт:** 8080
- **Структура:**
  - `CurrencyRateProviderApplication.java` — точка входа (main-класс)
  - `RateController.java` — REST-контроллер, обработчик HTTP-запросов
  - `RateResponse.java` — модель данных (POJO) для сериализации в JSON

## Сервис 2: Rate Printer

**Назначение:** Периодический опрос первого сервиса и вывод полученных данных на консоль.

### Логика работы

Сервис запускает бесконечный цикл, в котором с интервалом **5 секунд** выполняет HTTP GET-запрос к `http://localhost:8080/api/rates/usdrub`. Полученный курс валюты логируется в стандартный вывод (консоль). В случае ошибки соединения (например, первый сервис недоступен) выводится сообщение об ошибке, после чего цикл продолжается.

### Техническая реализация

- **Язык:** Java 17
- **Фреймворк:** Spring Boot 3.5
- **HTTP-клиент:** RestTemplate (встроенный в Spring Web)
- **Порт:** 8081 (для предотвращения конфликта с первым сервисом)
- **Структура:**
  - `RatePrinterApplication.java` — точка входа
  - `RatePrinterService.java` — сервис с циклом опроса и логирования
  - `RestTemplateConfig.java` — конфигурация HTTP-клиента

### Пример вывода

```
USDRUB: 81.27
USDRUB: 80.19
USDRUB: 81.83
```

## Принципы и подходы

1. **Микросервисная архитектура** — каждый сервис решает свою задачу независимо, имеет собственный порт и может быть развёрнут отдельно.
2. **Синхронное RPC-взаимодействие** — клиент отправляет запрос и ожидает ответ (REST over HTTP).
3. **Разделение ответственности (SRP)** — один сервис генерирует данные, второй их потребляет.
4. **Инкапсуляция** — каждый сервис имеет собственную конфигурацию порта, зависимостей и логики.
5. **Интерфейс как контракт** — оба сервиса взаимодействуют через формализованный JSON-формат.

## Сборка и запуск

### Требования
- Java 17+
- Maven (или Maven Wrapper)

### Сборка каждого сервиса
```bash
cd currency-rate-provider && ./mvnw clean package -DskipTests
cd rate-printer        && ./mvnw clean package -DskipTests
```

### Запуск
```bash
# Терминал 1 — Сервис 1
cd currency-rate-provider && java -jar target/currency-rate-provider-0.0.1-SNAPSHOT.jar

# Терминал 2 — Сервис 2
cd rate-printer && java -jar target/rate-printer-0.0.1-SNAPSHOT.jar
```

### Проверка
```bash
curl http://localhost:8080/api/rates/usdrub
